# BetterStructures 2.7.7 on Paper 26.3: structures missing from pregenerated terrain

> Short version for the issue tracker: [ISSUE.md](ISSUE.md). Workaround plugin: [BSPasteKeeper](BSPasteKeeper/).

**Affects:** BetterStructures 2.7.7 (MagmaCore 1.29-SNAPSHOT) on Paper 26.3. Tested with build 194, Java 25, WorldEdit 7.4.6, WorldGuard 7.0.19, EliteMobs 10.9.8 and Chunky 1.5.3.

**Symptoms**
- Terrain generated by Chunky, or by `/bs pregenerate`, gets few or no BetterStructures builds.
- `/bs pregenerate` places a handful in its first ~1,400 chunks and then stops, while its "Structures Generated" stat keeps counting.
- Builds sometimes appear only when a player is standing nearby.
- With heavy main-thread generation, the server can freeze and be killed by the watchdog. A wedged chunk leaves a visible hole in the terrain around a structure.

Class and method names below refer to the BetterStructures 2.7.7 jar. All measurements came from reflection on its static state, heap histograms, and region-file scans.

---

## Root cause

On Paper 26.3, a chunk loaded through `World#getChunkAtAsync` gets no grace period. Once the future completes and its temporary ticket is gone, Paper unloads the chunk, usually before the next tick. This happens even with `chunks.delay-chunk-unloads-by` set. Two 2.7.7 code paths assume the chunk is still loaded on a later tick.

### 1. Paste queue livelock (main cause)

`worldedit/Schematic` runs **one serial paste queue** (`pasteQueue` / `activePasteOperation`). Each step calls `operation.ready()` → `PasteChunkReadiness.ready(location)`:

1. The chunk isn't loaded, so it calls `release()`, starts `world.getChunkAtAsync(x, z, true)`, and returns `false`.
2. On a later tick, `pending.isDone()` is true, but `pending.join().isLoaded()` is already **false**. It sets `pending = null` and returns `false`.
3. The next tick it requests the chunk again, and the cycle repeats.

The active operation progresses only while something else (a nearby player, or pregen sync loads) keeps its chunk loaded. When nothing does, it never finishes, and every queued paste waits behind it.

Observed live:
- A `FitAnything$Finishing` operation (phase 0, pedestals) advanced 2 columns in 20 s. Its `chunks.pending` was always a completed future and `held` was `null`.
- During a 16k-chunk Chunky run, **79 `FitAnything$Preparation` + 38 `Schematic$ClipboardPasteOperation`** objects stayed frozen for over 90 s.

Contributing factors:
- `ClipboardPasteOperation`'s cursor iterates z innermost, so a single column often crosses a chunk boundary. `PasteChunkReadiness` holds **one** chunk and releases it at every crossing, so one paste re-acquires neighbouring chunks over and over. Each re-acquire is another chance to hit the race above.
- `ChunkPregenerator`'s "Structures Generated" counts `BuildPlaceEvent`, which fires before `Schematic.enqueue`. It counts *queued* builds, so the stats look healthy while nothing reaches the world.

### 2. New-chunk scan backlog (`listeners/NewChunkLoadEvent`)

New chunks go into `deferredNewChunks`. `drainDeferredNewChunks()` scans a chunk only if `world.isChunkLoaded(x, z)` is still true; otherwise it re-adds the key to the end of the `LinkedHashSet`. The drain handles at most 32 keys per tick within 5 ms.

Chunky-generated chunks unload before they are drained, so they stay in the set forever, and new chunks queue behind the stale ones. One Chunky session left **38,708 live `NewChunkLoadEvent$LoadingChunkKey`** objects. BetterStructures 2.1.0 scanned inside the `ChunkLoadEvent` and didn't have this problem.

### 3. Watchdog hangs from main-thread sync loads (possibly a Paper 26.3 issue that BetterStructures triggers)

Repeated watchdog kills all had the same signature:

```
[ChunkTaskScheduler] Chunk wait: [( <x>,<z>) in 'minecraft:overworld']
NewChunkHolder{... currentGenStatus=minecraft:initialize_light, requestedGenStatus=minecraft:full,
  generationTask=null, ... currentTicketLevel=33 ...}
Server thread: ServerChunkCache.syncLoad <- ... <- ChunkPregenerator.generateChunk   (or Entity.move for a player)
```

Each happened while the main thread was **synchronously** generating a chunk that was also being generated asynchronously. One trigger was `/bs pregenerate` (`chunk.load(true)`). The other was a fast-moving player next to a fresh BetterStructures fit, whose topology scan sync-loads neighbour chunks.

The wedged chunk never finishes lighting, so Paper sends neither it nor its neighbours to clients. A player moving into it blocks the main thread until the watchdog kills the server. The state is runtime-only: after a restart the chunk generates normally. Async-only generation (Chunky, ~32k chunks with BetterStructures active) never wedged.

## Suggested upstream fixes

1. **`PasteChunkReadiness`:** take a ticket *before* waiting on the chunk, for example `world.addPluginChunkTicket(x, z, plugin)`, then poll `isChunkLoaded` and release on `close()`. Or add the ticket inside the future's `thenAccept`, not on a later tick. Better still, pin the whole operation footprint for the lifetime of the paste. That removes both the race and the per-boundary ticket churn.
2. **`NewChunkLoadEvent`:** stop re-queuing unloaded keys forever. Scan in the event as 2.1.0 did, ticket chunks while they're deferred, or drop/reload stale keys. Bound the set.
3. **`ChunkPregenerator`:** use `getChunkAtAsync` with bounded concurrency instead of `chunk.load(true)` on the main thread. Count `BuildPasteCompleteEvent` for "Structures Generated".

## Workaround

### Install

1. Put `BSPasteKeeper/BSPasteKeeper-1.0.0.jar` in `plugins/`. It depends on BetterStructures.
   - SHA-256: `ea54844d7e4d969abfdc94c16901834148453c12bb5a76381ac9cbb5c7576fa2`
2. If you pregenerate with Chunky, add the JVM flag `-Dchunky.tickingLoadDuration=10` to your server start command. It makes Chunky hold each chunk for 10 s, so BetterStructures' deferred scan can still reach it (issue 2).
3. Recommended, against issue 3:
   - Set `chunks.prevent-moving-into-unloaded-chunks: true` in `config/paper-world-defaults.yml`.
   - Pregenerate with Chunky instead of `/bs pregenerate`, so players don't generate terrain during play.
4. Restart the server. On startup the log should show `[BSPasteKeeper] Pinning BetterStructures paste footprints.`

Chunks generated *before* installing the fix keep their missing structures. BetterStructures only places builds in newly generated chunks, so those areas need to be trimmed and regenerated.

### How it works

`BSPasteKeeper` (source in `BSPasteKeeper/src`) is a standalone plugin and changes no BetterStructures code.
- Every tick it reads `Schematic.activePasteOperation` through reflection.
- It computes the operation's footprint: `adjustedLocation` + `clipboard` for `ClipboardPasteOperation`, or `corner` + `FitAnything.schematicClipboard` (via `this$0`) for `Preparation` and `Finishing`. It holds plugin tickets on those chunks (up to 64) and releases them 5 s after the operation changes.
- Tickets load chunks asynchronously, so `PasteChunkReadiness` always finds its chunk loaded.
- Fallback: if an operation's footprint can't be read, it tickets the chunk from the pending `getChunkAtAsync` future when that completes.
- It never adds tickets in response to `ChunkLoadEvent`. Doing that cascades through neighbour-chunk loads.
- If the BetterStructures internals it reads don't exist (for example after an update), it logs a warning and disables itself.
- Every minute it logs `pastes started`, `pinned`, `queued` and `activeFor`. A healthy server shows `queued=0`.

### Results

Same world seed and BetterStructures grid, measured with `diagnostics/tools/bsscan.py`:

| Structure type | Fresh Chunky area, no workaround | Fresh 16,129-chunk Chunky area, with workaround | Control: world generated by BS 2.1.0 on 1.21.x |
|---|---|---|---|
| Underground shallow | 0/7 | 31/35 (89%) | 96/110 (87%) |
| Underground deep | 0/8 | 28/34 (82%) | 88/109 (81%) |
| Surface | 0/4 | 5/16 (31%) | 18/55 (33%) |

With the workaround, the run also created 14 EliteMobs boss arenas with WorldGuard regions. The paste queue stayed at 0, TPS held at about 19.6–20, and there were no wedged chunks or watchdog events.

### Build

```
javac --release 21 -cp paper-api-26.3.build.194-stable.jar -d out BSPasteKeeper/src/main/java/keeper/BSPasteKeeper.java
cp BSPasteKeeper/src/main/resources/plugin.yml out/ && jar cf BSPasteKeeper.jar -C out .
```

`BSPasteKeeper/build.gradle.kts` does the same thing with Gradle.

## Diagnostics

- **`diagnostics/BSDiag`:** a read-only plugin for temporary use. Every 10 s, for the primary world, it logs:
  - new-chunk counts, and whether each new chunk is still loaded 1–2 ticks later
  - the sizes of `NewChunkLoadEvent`'s queues
  - a reflective dump of `Schematic.activePasteOperation` and its `PasteChunkReadiness`
- **`diagnostics/tools/bsscan.py`:** predicts BetterStructures grid spots from the world seed and your `config.yml` spacing, then counts how many predicted chunks contain a BetterStructures loot container. Run it with `--help` for usage.
- **`diagnostics/tools/statusmap.py`:** prints saved chunk generation status. `--holes` lists wedged chunks: non-full chunks whose 8 neighbours are all full.
